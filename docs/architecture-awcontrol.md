# AWcontrol desktop architecture

The central owns navigation and window identity. The Rust editors own documents, undo, selection,
rendering and save prompts. Reparenting a live native window does not save, reload or copy a file.

## Current boundaries

- `Workspace.cs`: ordered pages, active page, editor lifetime and per-document actions.
- `DockingService.cs`: discovery of local editor sessions and actual OS move/drop events.
- `WindowChrome.cs`: edge resizing without document padding. The top-level form keeps its own
  icon, AppUserModelID, rounded frame and maximize/restore behavior.
- `TemplateCatalog.cs`: stable template IDs, app ownership and pt-BR display descriptions.
  Content is generated by the corresponding Rust engine using `file.new`.
- `HomeView.cs`: navigation, accessible actions, app-separated gallery, recent files and preferences.
- `EditorControl.cs`: bounded, authenticated loopback requests. It never accepts arbitrary commands.
- `Distribution.cs` / `Program.cs`: install/update detection and the Applications page.
- `shared/aw-workspace`: common profile, editor tabs, window buttons, resize geometry and forwarding.

## Session discovery and live docking

Windows editors expose an authenticated loopback endpoint on a dynamically assigned port when
launched alone. An explicit `--control` remains supported. The existing private token/key store is
used; discovery records contain no credentials or document contents.

`%APPDATA%/AlimentosWilson/sessions/<pid>.json` has `version: 1`, `pid`, `app` (0 Excel, 1 Word),
`port`, and `executable`. The receiver bounds the record size/count, checks the running process
image against the installed application, authenticates and verifies the live PID before embedding.
Stale records never launch processes. Closed processes are removed from the in-memory catalog.

Move a standalone window, or pull a native tab away from its strip, and drop over the AWcontrol
window. The cue identifies the target. The same process/HWND moves into the workspace and is
removed from the standalone list. With several native tabs, the whole window is transferred and
the internal tabs remain accessible; there is no silent loss of background documents. Moving just
one document out of a multi-document process is a separate ownership problem and is not claimed.

## Future communication

A communication feature should be a separate navigation module and domain service, with explicit
account/session ownership, versioned messages, cancellation, reconnection and bounded persistence.
It must not share editor-control credentials or use the document loopback channel as a remote
transport. There is no communication backend, account synchronization or messaging implemented by
this change. The current service/UI separation leaves that extension independent of editor lifetime.
